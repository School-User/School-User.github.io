UGREEN Mouse Driver

UGREEN's Linux support for this mouse is "plug it in and hope" — no speed curves, no button remaps. So I reverse-engineered the receiver's wireless protocol from scratch and built the missing settings app.

USB HIDGhidraPythonGTK4Hyprland

No Linux driver, no docs

UGREEN ships a Windows/macOS app ("KM Center") for configuring DPI, button remaps, and scroll behavior on their wireless mice — nothing for Linux. The receiver enumerates as USB 2b89:0043. To build an equivalent on Linux, I had to work out its wire protocol with no documentation to go on.

Finding the protocol

I pulled apart UGREEN's own Mac agent binary with Ghidra to see how it talks to the receiver. It uses a vendor HID page (0xFFB5) on USB interface 1, with 8-byte output reports shaped like B5 33 <read/write> <cmd> a0 a1 00 00. That static analysis gave me the easy commands — read/set serial, battery level, DPI, factory reset — straight away.

But live traffic testing turned up a wrinkle: this receiver's USB ID shares its HID descriptor with UGREEN's M520 receiver, so I assumed it spoke the same protocol family. It doesn't. Sending real M520-style packets to it got silence. On wake, the receiver instead broadcasts an unprompted packet tagged 0x67 — a protocol UGREEN's own official software (on either OS) doesn't implement at all. For this receiver, UGREEN's app only does host-side remapping; it was never actually talking native protocol to the hardware.

Building the Linux side

With the known command set (DPI, battery, serial, button mask) mapped, I built ugmouse.py, a CLI for reading and writing those settings directly over the vendor HID interface, then a proper GTK4/libadwaita settings app on top of it. It writes a Hyprland Lua config (per-device speed, acceleration, scroll direction, left-handed mode, and button remaps via hl.bind device filters) so changes apply system-wide, not just inside one app.

Getting button remaps working on Hyprland 0.56 had its own sharp edges — a release-bind only matches inside whatever submap was active at press time, so a naive submap-based combo can strand you with every keybind dead until you cycle back. The fix was using always-present scroll binds toggled with Keybind:set_enabled instead of submap switching.

Shipped

Published as an open-source repo with the full protocol table in the README, so the next person with this receiver doesn't have to redo the Ghidra work.
