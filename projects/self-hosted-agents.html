Self-Hosted AI Agents

An AI agent that runs 24/7 on my own hardware, reachable over Telegram and email, doing scheduled research so nothing about it leaves my network.

ProxmoxsystemdTelegramOllamaCron

Why self-host an agent

I run an always-on AI agent in a dedicated VM on my home Proxmox server instead of using a hosted service, mainly so it can run scheduled, somewhat personal tasks — daily research digests, reminders — using a local model, with nothing about those requests leaving my own network. It's reachable over Telegram and a dedicated email address, and runs two standing jobs: a daily internship search and a daily AI/cybersecurity news digest, both deduplicated against what it's already sent me so I don't get repeats.

Only one instance can poll the bot

Telegram bots only allow a single process to long-poll for updates at a time. I'd originally run the agent on my laptop; moving it to the always-on VM meant explicitly stopping and disabling the laptop's copy of the gateway first — otherwise both instances fight over the same bot token and messages get dropped or duplicated.

The timezone bug that fired a 2am alert

The VM came up with its clock on UTC by default. An 8:00am daily cron job silently became a 2:00am job in my actual timezone — the kind of bug that's invisible until you happen to be awake at 2am and your phone buzzes. Fixed by setting the VM's timezone explicitly rather than assuming cron's "daily at 8" means what you think it means.

Search engines don't like being automated

The agent's web search initially went through a self-hosted SearXNG instance, which worked until it didn't — most of the backing search engines started CAPTCHA-walling or rate-limiting requests coming from my home IP, and the one that didn't was returning results so stale they included Titanic-era search hits for current-events queries. Switched the agent's search backend to a keyless API instead, which trades away a bit of self-hosted purity for actually working reliably.

Smaller gotcha worth remembering: the agent's own packaged browser tooling installs Chrome somewhere its own detection logic doesn't check, so browser-based tools silently disabled themselves with no error — fixed with one explicit environment variable pointing at the real binary path. The lesson: "silently disabled" bugs in agent tooling are worth checking for explicitly, since they don't throw anything to debug.

What it actually does

  • Daily internship search, results deduplicated against a running log so I only see new postings
  • Daily AI + cybersecurity news digest delivered to Telegram
  • Reachable for ad-hoc requests over Telegram and a dedicated email inbox, with a strict allowlist of senders it will actually act on
  • Runs on a local Ollama model, so conversation content stays on my own hardware
